# low_tide — deployment framework

Deploys the **low_tide** intertidal data-analysis web app onto the existing
DigitalOcean droplet **`hwitw`** (`164.92.75.176`, sfo3), sharing resources with
the HWITW app already running there. The app source is deployed **verbatim** —
this folder is only the deployment scaffolding around it.

**Source:** public repo <https://github.com/hig314/low_tide> (public since
2026-10-18). The app's authors push to `deploy/app/`. The rest of `deploy/` is
the hosting layer. These docs contain no credentials and none should ever be
added: tokens and SSH keys stay on the operator's machine and the droplet.

## What the app actually is

Mostly static: the pages and JavaScript run in the browser on pre-baked data
blobs generated by `download.py` (the refresh cron's job, see `refresh/`). Since
2026-10-18 there is one backend call, from the NMDS page:

- **Pages:** `static/main/index_lt.html` (the main tool) and
  `static/NMDS/index_NMDS.html` (NMDS ordination), each with an `info.html`.
  Shared code lives in `static/ltda_root.js` and `static/libs/`; the data blobs
  stay at the top of `static/`, and pages load everything through `../`.
- **URLs:** the pages' links to each other are hard-coded to `/static/...` (the
  app's Flask dev layout). Our docroot is `static/`, so `nginx.conf` serves
  `/static/X` as an alias of `/X`, 302s `/` to `/static/main/index_lt.html`, and
  301s the old `/index_lt.html` there too.
- **Backend:** the NMDS page POSTs LZW-compressed survey vectors to
  `/requests/NMDS`. The app's `webapp.py` (with `MDS.py` + `lzw.py`) answers it
  using scikit-learn's non-metric MDS. We run it **unmodified** under gunicorn in
  the `lowtide-api` container; nginx proxies `/requests/` to it. Its other routes
  (`/wxapp/*`) are HWITW leftovers and broken; nothing calls them.

## How it's reached — domain + its own "naked IP"

Since 2026-09-21 the public URL is the domain:

    https://lowtidedata.org/        (www. 301s here; HTTP 308s to HTTPS)

`lowtidedata.org` is registered at Cloudflare Registrar (hig314@gmail.com). DNS is
two A records, `@` and `www` → `209.38.5.101`, with the Cloudflare proxy **OFF**
(grey cloud). Caddy has a site block per name (see `Caddyfile`), auto-issues the
Let's Encrypt cert on first request and renews it; certs persist in
`/opt/caddy/data/caddy_data/`. If the Cloudflare proxy is ever turned on, set its
SSL mode to Full (strict) first, or the site breaks.

Underneath, a DigitalOcean **Reserved IP, `209.38.5.101`**, is attached to the
droplet, giving low_tide its own bare URL that still works as an HTTP fallback:

    http://209.38.5.101/

HWITW keeps the droplet's primary IP, `http://164.92.75.176/`.

DO routes the reserved IP onto the droplet's `eth0` via 1:1 NAT, but the browser
still sends `Host: 209.38.5.101`. So the shared **Caddy** proxy (which owns
`:80`/`:443`) splits the two apps purely on the Host header — no second listener,
no per-interface binding. See `Caddyfile`.

## Files

- `docker-compose.yml` — two services, deployed to `/opt/lowtide/`:
  - `lowtide` (`nginx:alpine`): serves `app/static/` read-only; on the shared
    external `web_external` network (Caddy) and the private `lowtide_internal`.
  - `lowtide-api`: built from `api/Dockerfile`; `app/` bind-mounted read-only at
    `/app`. Only on `lowtide_internal`. Capped at `cpus: 0.75`, `mem_limit: 768m`.
- `api/Dockerfile` — `python:3.12-slim` + the app's own `requirements.txt` +
  gunicorn (1 sync worker, 120 s timeout, non-root). Code isn't baked in, so a
  code-only handoff needs no rebuild; dependency changes do (`--build`).
- `nginx.conf` — the `/static/` alias and redirects, `Cache-Control: no-cache`
  on `.js`/`.html` (cheap ETag revalidation, so in-place script changes are
  never masked by browser caches), and the `/requests/` proxy with guardrails:
  per-client rate limit 10/min, burst 5, 429 beyond (client IP taken from
  Caddy's `X-Forwarded-For`), 1 MB body cap, 120 s read timeout.
- `app/` — verbatim copy of the low_tide project, pushed by its authors.
- `refresh/` — the data-refresh cron (see `refresh/README.md`).
- `Caddyfile` — the updated `/opt/caddy/Caddyfile` (domain blocks + Host-based IP split). Reference copy.
- `opt-README.md` — reference copy of the droplet's `/opt/README.md`.

**NMDS cost:** CPU-bound and roughly quadratic in surveys. On the droplet under
the 0.75-CPU cap, 400 rows take ~14 s, 100 rows ~1 s; a full Seldovia run is ~200
rows. The API idles at ~130 MB. One worker means concurrent requests queue.

## The one Linux fix (no source edit)

`index_lt.html` loads `temp_data.js`, but the file is `Temp_data.js`. The dev's Mac
filesystem is case-insensitive so it never mattered; Linux is case-sensitive and
would 404 the "Show temperature" data. We create a lowercase **alias at deploy
time on the Linux host** (the two names can't coexist on the Mac, so it can't live
in this repo):

    cp /opt/lowtide/app/static/Temp_data.js /opt/lowtide/app/static/temp_data.js

## Deploy / update

From this `deploy/` folder. The six data-blob excludes are deliberate: the cron
owns live data, and the two `*_locations.js` blobs exist only on the droplet, so
without their excludes `--delete` would remove them from the live site.

    # 1. push framework + app to the droplet
    rsync -az --delete --exclude '.DS_Store' --exclude '__pycache__' --exclude '._*' \
      --exclude 'static/seldovia_sheet.js' --exclude 'static/costal_studies_sheet.js' \
      --exclude 'static/Temp_data.js' --exclude 'static/temp_data.js' \
      --exclude 'static/seldovia_locations.js' --exclude 'static/costal_studies_locations.js' \
      docker-compose.yml nginx.conf api app  root@164.92.75.176:/opt/lowtide/

    # 2. case-fix alias, perms, then rebuild/recreate. --force-recreate matters:
    #    rsync replaces nginx.conf with a new inode, and a single-file bind mount
    #    keeps showing nginx the old one until the container is recreated.
    ssh root@164.92.75.176 '
      cp -f /opt/lowtide/app/static/Temp_data.js /opt/lowtide/app/static/temp_data.js
      chmod -R a+rX /opt/lowtide/app /opt/lowtide/api
      cd /opt/lowtide && docker compose up -d --build --force-recreate'

    # 3. SOP: manual data refresh after every code deploy
    ssh root@164.92.75.176 'REFRESH_BACKOFF=5 /opt/lowtide/refresh/refresh.sh; tail -5 /opt/lowtide/refresh/refresh.log'

Data blobs are refreshed on the droplet by the cron, not locally.

If the `Caddyfile` changes, copy it to `/opt/caddy/Caddyfile` and reload:

    scp Caddyfile root@164.92.75.176:/opt/caddy/Caddyfile
    ssh root@164.92.75.176 'docker exec caddy caddy reload --config /etc/caddy/Caddyfile'
